- High-severity finding: individual-session paid reconciliation read current refunds only after committing payment evidence and only when charge refunded totals indicated a refund. Pending/failed refunds could be missed before booking confirmation if refund webhooks were missing or reordered.
- Additional finding: refund reconciliation could overwrite stored refunded/pending/failed aggregates or terminal refund status without matching ledger evidence.

Provider references rechecked 2026-10-14: Stripe documents that [event order is not guaranteed](https://docs.stripe.com/webhooks#event-ordering), and its [Refund object](https://docs.stripe.com/api/refunds/object) distinguishes pending, requires-action, succeeded, failed and canceled states. Reading current refund inventory before fulfillment is the engineering response tested here, not evidence that any hosted Stripe transaction succeeded.
