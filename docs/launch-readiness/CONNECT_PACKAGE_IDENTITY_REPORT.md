## Reproduced Finding

**P1:** `ensureConnectAccount` checked only booking payment history before reserving a new Stripe account. Package payment/checkout history was omitted. With a missing trainer `stripeAccountId`, existing package evidence did not prevent new account creation. This breaks the existing identity-preservation/reconciliation rule; no real provider replacement or misdirected funds were observed in this local reproduction.

Affected routes: `POST /api/payments/connect` and its legacy adapter `POST /api/trainer/stripe-connect`. Local synthetic trainer owns a historical package purchase with no current connected-account link. Each route is exercised with eight independent evidence variants: saved Checkout Session, PaymentIntent, charge, transfer, successful/refunded/partially-refunded status, or a durable checkout attempt without a provider response ID.

Expected: 409 requiring reconciliation, no provider calls/new Connect attempt, unchanged purchase and missing account link. Baseline actual: **all 16 guarded-history cases returned 200**, not 409. Four compatibility cases passed; 30 other cases were intentionally not selected.
