This is a local synthetic embedding reproduction, not evidence of a real attack or a cross-site authenticated exploit.
- Fix in `next.config.js`: path-wide `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: no-referrer`. Same-origin referrers are omitted too, avoiding disclosure of authentication query strings through navigation. No credentials, cookies, permissions, CORS or provider settings changed.
- The CSP is deliberately limited to embedding ancestry. It does not add script-src, connect-src or frame-src restrictions that could break Stripe navigation or embedded provider content. It is **not a comprehensive XSS CSP**. Primary references: [Next response-header configuration](https://nextjs.org/docs/app/api-reference/config/next-config-js/headers), [frame-ancestors semantics](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).
